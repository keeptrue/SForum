# Environment variables and secrets

[← Deployment](../deployment.md)

Production configuration has exactly one file: `.env.production` in the
install directory. It serves two purposes, and the boundary between them is
often misunderstood:

1. **Compose interpolation**: `${VAR}` in `compose*.yaml` is read from
   `--env-file`.
2. **Container runtime environment**: only variables written in a service's
   `environment:` list enter the container. `.env.production` is not the
   container's `env_file`.

So "written into `.env.production`" does not mean "the application can read
it". The default Compose files already pass through the common variables;
advanced diagnostic variables need a Compose override, see the end of this
page.

## Files and permissions

```sh
cp .env.production.example .env.production
chmod 600 .env.production
```

- Files generated by the configuration wizard are also `0600` and never
  overwrite an existing file.
- `docker compose` reads `.env` by default, not `.env.production`; every
  command must carry `--env-file .env.production`.
- Do not commit `.env.production` to the repository, and do not paste it into
  tickets or chat logs.
- `APP_DOMAIN` is only used by the host Caddy example and never enters the
  application container.

## Minimum required list

`deploy.sh` validates the rules below before touching the database; a manual
deployment should satisfy the same contract.

| Variable | Rule |
| --- | --- |
| `APP_ENV` | must be `production` |
| `APP_URL` | `http://` or `https://`, no spaces |
| `NUXT_PUBLIC_ADMIN_ROUTE_PREFIX` | a safe path starting with `/` |
| `POSTGRES_DB` / `POSTGRES_USER` | letters, digits, `_`, `.`, `-` only |
| `POSTGRES_PASSWORD` | at least 32 characters; letters, digits, `.`, `_`, `~`, `-` only |
| `DATABASE_URL` | must point at `postgres:5432/<POSTGRES_DB>` |
| `REDIS_ADDR` | must be `redis:6379` |
| `REDIS_PASSWORD` | at least 32 characters |
| `SESSION_HASH_SECRET` | at least 32 characters |
| `IDENTITY_SUBJECT_HMAC_SECRET` | at least 32 characters |
| `APP_OPTION_ENC_KEY` | 64-character hex |
| `ALTCHA_SECRET` | at least 32 characters |
| `MARKETPLACE_ED25519_PUBLIC_KEY_HEX` | 64-character hex |
| `NUXT_PUBLIC_API_BASE_URL` | must be `/api/v1` |

Generate secrets:

```sh
openssl rand -hex 32
```

Generate each secret separately. Do not reuse development defaults, and do not
use the same value for the database, Redis, sessions, and encryption.

## Ports and entrypoints

| Variable | Default/example | Notes |
| --- | --- | --- |
| `HTTP_HOST` | `0.0.0.0` | API listen address inside the container |
| `HTTP_PORT` | `8080` | API port inside the container |
| `HTTP_BODY_LIMIT` | `67108864` | hard API request body limit, 64 MiB |
| `WEB_PORT` | `3000` | Web port on the host loopback |
| `API_PORT` | `18080` | API/WebSocket port on the host loopback |

`WEB_PORT` and `API_PORT` bind `127.0.0.1` only; the public entrypoint is the
host reverse proxy.

## PostgreSQL

| Variable | Default/example | Notes |
| --- | --- | --- |
| `POSTGRES_DB` | `sforum` | database name |
| `POSTGRES_USER` | `sforum` | database user |
| `POSTGRES_PASSWORD` | no safe default | must be replaced with a high-entropy value |
| `DATABASE_URL` | `postgres://sforum:<password>@postgres:5432/sforum?sslmode=disable` | connection string inside the container |
| `MIGRATE_ON_STARTUP` | `true` | when `true` the API migrates at startup; the wizard and `deploy.sh` write `false` and migrate explicitly |
| `DATABASE_MAX_CONNS` | `10` | pool limit shared by the API and its embedded Worker |

PostgreSQL networking inside Compose does not enable TLS. An external database
is an advanced deployment: switch to `verify-full` as the provider requires and
configure trusted certificates; the configuration wizard offers no external
database option.

## Redis

| Variable | Default/example | Notes |
| --- | --- | --- |
| `REDIS_ADDR` | `redis:6379` | built-in Compose Redis address |
| `REDIS_PASSWORD` | no safe default | Compose enables `--requirepass` for Redis |

To use an external Redis without a password, blank `REDIS_PASSWORD` and adjust
`--requirepass` in `compose.yaml` at the same time; do not change only one
side.

## Queues and Worker

The API always embeds the River Worker; there is no separate Worker switch.

| Variable | Default/example | Notes |
| --- | --- | --- |
| `WORKER_SHUTDOWN_TIMEOUT` | `30s` | wait for jobs to finish on shutdown |
| `JOB_QUEUE_CRITICAL_WORKERS` | `4` | critical queue concurrency |
| `JOB_QUEUE_DEFAULT_WORKERS` | `8` | default queue concurrency |
| `JOB_QUEUE_SEARCH_WORKERS` | `6` | search indexing concurrency |
| `JOB_QUEUE_MAIL_WORKERS` | `4` | mail concurrency |
| `JOB_QUEUE_NOTIFICATIONS_WORKERS` | `6` | notification concurrency |
| `JOB_QUEUE_MAINTENANCE_WORKERS` | `2` | maintenance task concurrency |

When queues stay busy, prefer raising `DATABASE_MAX_CONNS` and observing
PostgreSQL, or lowering the affected queue concurrency; do not raise River
concurrency without a bound.

## Extensions and trust

| Variable | Default/example | Notes |
| --- | --- | --- |
| `EXTENSION_ROOT` | `/var/lib/sforum/extensions` | persistent directory for installed extensions |
| `BUILTIN_EXTENSION_ROOT` | `/app/extensions/builtin` | built-in extension directory |
| `EXTERNAL_EXTENSION_ROOTS` | empty | optional, comma-separated container paths; requires matching read-only volumes |
| `SFORUM_V3_TRUST_CHALLENGES` | `true` | enable exact-artifact trust confirmation |
| `SFORUM_V3_TRUST_CHALLENGE_TTL` | `5m` | trust confirmation lifetime |
| `SFORUM_SAFE_MODE` | empty (equivalent to `false`) | set to `true` and restart the API to skip plugin startup; change it back after recovery |

`EXTERNAL_EXTENSION_ROOTS` must be container paths; host paths are not
accepted.

Public L2 (`components[].l2Component` and content-surface styles) has **no
separate switch** and is always enabled: once an extension is enabled and its
exact artifact is trusted, its prebuilt ESM/CSS reaches the browser. The former
`SFORUM_V3_PUBLIC_L2` variable is removed; setting it has no effect.

It builds on exact-artifact trust, so `SFORUM_V3_TRUST_CHALLENGES=false` closes
public L2 for the whole instance (that is the non-production default in
`.env.example` and `compose.yaml`; production defaults to `true`). To close a
single extension, disable it or revoke its exact-artifact trust; to close every
extension, set `SFORUM_SAFE_MODE=true`.

## Sessions, identity, and encryption

| Variable | Default/example | Notes |
| --- | --- | --- |
| `SESSION_HASH_SECRET` | no safe default | server-side session signing; rotating it invalidates every existing session |
| `IDENTITY_SUBJECT_HMAC_SECRET` | no safe default | HMAC for external subject digests; rotating it changes the digests |
| `APP_OPTION_ENC_KEY` | no safe default, 64-character hex | AES-256-GCM encryption for sensitive option values; old values become unreadable after rotation |
| `MARKETPLACE_ED25519_PUBLIC_KEY_HEX` | no safe default, 64-character hex | verification public key for the Marketplace signed index |
| `MARKETPLACE_ED25519_KEY_ID` | `marketplace-primary` | public key identifier |

The wizard generates a local Marketplace public key for the
`deployment-local-untrusted` purpose so unknown indexes stay locked. To adopt
the official Marketplace you must replace it with the official public key and
key ID; never put the private key in the repository or containers.

## CSRF and reverse proxy

| Variable | Default/example | Notes |
| --- | --- | --- |
| `CSRF_TRUSTED_ORIGINS` | `https://forum.example.com` | allowed public origins; derived from `APP_URL` when empty |
| `TRUST_PROXY` | empty (production-equivalent `false`) | whether forwarded headers are trusted |
| `TRUSTED_PROXIES` | empty | reverse proxy addresses or CIDR ranges, comma-separated |
| `TRUST_PROXY_PRIVATE` | empty (production-equivalent `false`) | whether private-network sources are trusted |
| `TRUST_PROXY_LOOPBACK` | empty (production-equivalent `false`) | whether loopback sources are trusted |

Production trusts no network range by default. Enable `TRUST_PROXY` only when
deployed behind a host reverse proxy, and set `TRUSTED_PROXIES` to the proxy
address, for example `127.0.0.1/32` for a same-host Caddy. Do not write
`0.0.0.0/0`; blanket trust lets a forged `X-Forwarded-For` bypass rate limiting
and audit logging.

`compose.yaml` already passes these four variables through to the `api`
container. `PROXY_HEADER` defaults to `X-Forwarded-For`; inject it through an
override when it must change.

### AI provider egress

Production allows only `https` and rejects endpoints that resolve to private,
loopback, or reserved addresses. `SFORUM_AI_ALLOW_PRIVATE_ENDPOINT=true` is for
development against a local model service (Ollama, vLLM, and similar) only;
production always treats it as `false`. To reach an internal model service in
production, put an HTTPS reverse proxy in front of it.

## Advanced variables that need an override

The variables below are not in the default Compose `environment:` list, so
writing them into `.env.production` does not put them into the container. Add
an override file when needed, for example `compose.local.yaml`, and append
`-f compose.local.yaml` to every Compose command.

| Variable | Purpose |
| --- | --- |
| `PPROF_ENABLED` / `PPROF_ADDR` | API pprof, off by default; the address must be loopback |
| `WORKER_PPROF_ENABLED` / `WORKER_PPROF_ADDR` | standalone Worker pprof (the current topology uses no standalone Worker) |
| `GOMEMLIMIT` | Go runtime soft heap limit, for example `512MiB` |
| `HTTP_READ_TIMEOUT` / `HTTP_WRITE_TIMEOUT` / `HTTP_IDLE_TIMEOUT` | HTTP timeouts |
| `SESSION_IDLE_TIMEOUT` / `SESSION_ABSOLUTE_TIMEOUT` / `SESSION_RENEWAL_INTERVAL` | session lifecycle |
| `LIMITER_WINDOW` | write request rate-limit window |
| `DATABASE_CONNECT_TIMEOUT` / `DATABASE_MAX_CONN_IDLE_TIME` / `DATABASE_MAX_CONN_LIFETIME` | connection pool details |
| `REDIS_DIAL_TIMEOUT` / `REDIS_READ_TIMEOUT` / `REDIS_WRITE_TIMEOUT` | Redis timeouts |
| `SFORUM_AI_ALLOW_PRIVATE_ENDPOINT` | development only, to reach a local model server directly; always `false` in production |

Override example:

```yaml
services:
  api:
    environment:
      GOMEMLIMIT: "512MiB"
      PPROF_ENABLED: "true"
      PPROF_ADDR: "127.0.0.1:6060"
```

pprof listens only on the container loopback and must not be exposed directly
through `ports:`. For collection steps see
[troubleshooting](./troubleshooting.md).

## Verification

```sh
docker compose --env-file .env.production \
  -f compose.yaml -f compose.prod.yaml -f compose.release.yaml config --quiet

./deploy.sh --action status
```

`config --quiet` only validates the Compose expansion, not whether the
application is healthy; for health checks see
[manual Compose deployment](./manual.md).
