# SForum v3.1.5 发布说明

v3.1.5 是 `v3.1.4` 之后的**修复版**，只做一件事：修掉「公开页文档 CSP 拦掉宿主自己的
内联样式与内联脚本」这个线上可见缺陷，并把文档 CSP 从「只有挂 L2 岛的页才下发」扩到
**所有公开页**。无迁移、无 schema 变更、无破坏性 API 变更。

## 问题

部分公开页（主题页、分类页、标签页等挂了 L2 组件或区域 widget 的页）出现：

- 设计 token 丢失：Nuxt UI 的 `--ui-*` 变量为空，配色回落到灰色；
- 图标、进度条、分类色、徽章档位、编辑器工具条位置等**所有 `:style` 驱动的样式全部失效**；
- 控制台每页几十条 `Applying inline style violates the following Content Security Policy directive 'style-src 'self''`，
  外加少量 `Executing inline script violates … 'script-src 'self''`。

真实 Chrome 实测（修复前，同一页面）：**41 条 `securitypolicyviolation`**，按指令分布
`style-src-elem` 19 / `style-src-attr` 18 / `script-src-elem` 4，`--ui-primary` 为空值，
18 个内联样式候选无一生效。

## 根因

`publicPageDocumentPolicy()` 把 L2 扩展片段与 Host 基线合并成**整份 SSR 文档**的
`Content-Security-Policy`，旧基线是 `script-src 'self'; style-src 'self'`。

但 Nuxt SSR 文档按构造就违反这两条：

- Nuxt UI 把设计 token 写成 `<style id="nuxt-ui-colors">`；Nuxt Icon 在 SSR 期输出 `<style>`；
  Vue 模板里的 `:style` 属性（实测 75 处）——而 **style 属性在规范上永远无法携带 nonce/hash**。
- Nuxt UI 注入内联平台探测脚本（`document.documentElement.classList.add('ui-macos')`）。

并且旧代码里还有一条「合并后可执行指令必须恰好 `['self']`」的断言：一旦基线放宽，它会
让策略端点恒返回错误，`applyPublicPageDocumentPolicy` 拿到 `null` 后**静默不写 CSP 头**——
表面更安全，实际整页失去策略下发且无任何报错。

该缺陷长期潜伏，`e9ae49af6`（public L2 永远开启）拆掉 `SFORUM_V3_PUBLIC_L2` 开关后，
下发面从「几乎没有」变成「几乎每个公开页」，才在生产暴露。

## 修复

**1. 基线改为「宿主文档可满足的来源白名单」**

```
base-uri 'none'; connect-src 'self'; default-src 'none'; font-src 'self';
form-action 'self'; frame-ancestors 'none'; img-src 'self' blob: data: https:;
media-src 'self'; object-src 'none'; script-src 'self' 'nonce-…';
style-src 'self' 'unsafe-inline'; worker-src 'self'
```

- `style-src` 加 `'unsafe-inline'`：style 属性无法 nonce，这是唯一可行解。
- `img-src` 加 `https:` / `data:` / `blob:`：全站下发后，Gravatar 头像与富文本外链图
  必须能加载。CSP 在这里管**代码来源**，不管内容图片；`script-src` / `style-src` /
  `worker-src` 的代码边界一点没动。
- `script-src` 保持严格，改为**按请求发 nonce**：Nitro `render:html` 给 `head` 与
  `bodyAppend` 里无 `src` 的内联脚本打标，与响应头里的 nonce 同源同值。
- 收窄旧断言：可执行指令只允许**扩展片段**贡献 `'self'`，宿主基线不受该断言约束。

**2. 所有公开页无条件下发**

- 去掉「有 L2 岛才写头」的门槛；零 ref 页用**模块级缓存的 Host 基线**（in-flight 去重、
  失败不缓存、HMR 时失效），实测 3 次 pageview 只付 1 次策略端点往返。
- per-page 策略拉取失败时**回退到基线**（仍写头），不再整页无策略。
- 主题外壳与正文岛会各写一次头，规则改为「具体胜基线」：内层基线不得覆盖外层逐页策略。

**3. dev 与生产下发同一份 CSP**

删掉 dev 短路，缺陷在开发期就能暴露；dev 分支仅额外放行 Vite HMR websocket 与
Iconify 兜底主机（`import.meta.dev` 之外不生效，生产头逐字不含这些源）。

## 修复过程中抓到的第二个回归

生产构建门禁发现：主题页客户端渲染的图标会去请求公共 Iconify API，被 `connect-src 'self'`
拦掉后**图标静默消失**（每页 3 条违规）。根因是 `@nuxt/icon` 的 `DEFAULT_RESOURCES` 只有
1 个主机，`isDefaultProvider` 判定恒假 → provider 永不替换，而 `@iconify/vue` 默认实际有
3 个主机；`fallbackToApi:false` 管的是另一条分支，盖不住。

修法：新增 `apps/web/app/plugins/icon-local-provider.client.ts`，把默认 provider 指向
**同源** `/api/_nuxt_icon`。公共主机请求从 3 条降为 0 条，生产 CSP 一个口子没开。

这个 bug 在 dev 环境永远看不见（dev 放行了那三个主机），只有生产构建门禁能抓到。

## 新增的回归门

`tests/validate-document-csp.mjs`：真实 Chrome + CDP（无 Playwright 依赖），断言

1. 目标页真的下发 `Content-Security-Policy`（缺头即失败）；
2. `securitypolicyviolation` 为 0，有则逐条打印；
3. `--ui-primary` 非空、至少一个内联样式真的生效；
4. `script-src` 恰好一个 nonce，且与**同一次导航**渲染出的内联 `<script>` 一致
   （跨请求比对在 per-request nonce 下永远不可能匹配）；
5. `style-src` 不含 nonce/hash（CSP3 下会让 `'unsafe-inline'` 失效）。

退出码：`0` 通过 / `1` 失败（含页面缺头且策略端点可达）/ `2` 环境未就绪。
`--self-test` 用本地夹具证明门禁本身能抓到三类违规，已接进 `scripts/test.sh` 的 static 线
且**必须通过**；真实服务那一跑在 CI 里因无服务记 SKIP。

## 升级注意

- 所有公开页开始带 `Content-Security-Policy` 响应头。若站点把 API 部署在独立域名，
  `connect-src` 会自动带上该 origin（代码已处理）；若有页面依赖站外接口且不在扩展声明的
  `connect-src` 里，升级后会当场被拦——这是最可能收到反馈的点。
- 外部图片靠 `img-src https:` 放行；`data:` / `blob:` 同样放行。
- `admin` / `auth` / 错误页不走公开页外壳，仍不下发文档 CSP（与「公开页」口径一致）。
- 无迁移、无 schema 变更；回滚即回滚镜像 tag。
- **发版清单必须手动跑一次**：CI 里 CSP 门禁因无服务会 SKIP，所以发版前要在有数据的实例上
  跑 `SFORUM_CSP_PATHS=/,<一个主题页> node tests/validate-document-csp.mjs`。

## 已知缺口

- 主题模板路径会写两次头（外壳 + 正文岛），已按「具体胜基线」收敛，但「每响应恰好一次」
  的契约描述不再字面成立。
- 缓存让 `X-SForum-Document-Policy-Digest` 在扩展启停导致 graphDigest 变化后保持旧值，
  直到进程重启。
- 前端测试里的基线是 Go `publicPageHostBaselinePolicy()` 的手抄副本，跨语言只有浏览器
  门禁在守。
