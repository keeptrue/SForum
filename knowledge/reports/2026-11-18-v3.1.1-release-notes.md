## 新功能

### 扩展运行时：恢复出口与 dev 自愈

- **`recovery republish-artifact` 恢复出口** —— `sforum recovery republish-artifact <extension-id> --reason TEXT [--confirm-token TOKEN]`（同 `sforum extension recovery republish-artifact`）：把一个指向不可用制品的 publication 成员**重指向同版本的另一份自洽制品**，并追加一版新 publication；`--reason` 必填，不带 `--confirm-token` 时只打印 `DEFECT` / `CANDIDATE` 的 dry run。不启动 SForum、不加载插件代码、不热恢复。`afbc1676d`
- **`extension verify-artifacts` 只读自检** —— 逐成员校验「目录存在 + 目录名等于树摘要 + manifest `backend.digest` 等于文件摘要」，输出 `checked N artifact(s)` 与逐条 `DEFECT`，退出码 0 / 1 / 2。CI 与 dev 启动前都能跑。`afbc1676d`
- **dev 自愈** —— 启动期只读自检报出带坐标的制品缺陷后，**仅** `APP_ENV=development && !SafeMode` 才尝试把坏 publication 重指向同 `extensionId@version` 的自洽候选（已安装 root、`storage/builtin-dev`、`EXTERNAL_EXTENSION_ROOTS`）；走 `PublishPluginRuntimeArtifactRepairTx` 追加 `reason=recovery` 的 revision，**零写盘**、不改既有 `extension_versions` 行，自愈出的 revision 仍要过发布期闸门。已知限制：一次启动最多修复一个成员。`6643af3f0`
- **后台补两个只读页** —— `/control-panel/extensions/migrations` 呈现 `GET /admin/extensions/{id}/migrations` 的 path / status / checksum / appliedAt / message（状态只按契约的 `recorded` / `applied` / `failed` 渲染，`recorded` 不等于「已执行」）；`/control-panel/extensions/added-pages` 列出主题通过 `action: add` 贡献、`/admin/pages` 看不见的页面。`75dc6fe87`

### 账号与安全操作

- **「我的内容」** —— 账号设置新增 `/settings/content`（页面 `forum.settings.content`，`Replaceable: false`），消费 `GET /api/v1/me/content-review`，分「待审」/「被退回」两列表；被退回项固定渲染审核意见块，无 `reviewNote` 时明确说明「没有留下说明」。`c679e058b`
- **用户详情撤销全部 API 令牌** —— `DELETE /users/{userID}/api-tokens`（`user.manage`；目标是 `super_admin` 时只允许 `super_admin` 操作），返回撤销条数并写 `api_token.admin_revoke_all` 审计。`469295770`
- **强制下线加确认** —— 与既有危险动作同一道确认护栏。`3a1e0afa7`

### 可观测性

- **人机验证配置读失败降级** —— `humanverify` 配置读取失败时写入结构化 `warn` 并留档决策，不再让一次配置读异常吞掉整条链路。`658b6a503`

## 修复

### 发布链路缺口（发版当天收口）

三条同属一个形状：校验当时只存在于 release workflow 里，只有推 tag 之后才会跑，于是 `main` 的 CI 全绿而发版当天红。

- **darwin 交叉编译恢复** —— `pluginprocess/hardening_unix.go` 用 `//go:build unix` 包住整个文件，却在里面调用只有 Linux 才有的 `unix.Prlimit`，`GOOS=darwin go build ./...` 直接编译失败，两个 darwin 资产 job 全红。按「哪个平台真的能做到」拆开：`hardening_linux.go` 留 prlimit 实现（Linux 行为逐字未变），`hardening_unix_noprlimit.go`（`unix && !linux`）是显式 no-op 并在注释里写明为何不能用 `setrlimit` 顶替，`hardening_unix.go` 只留进程组语义；同一类缺陷在测试里还有一处（`TestProtocolStartLowersOpenFileLimit` 也读 `unix.Prlimit`，只在 darwin `go vet` 下炸），用例连同常量迁到 `plugin_process_linux_test.go`，断言一条没少。`23fad3e3b`
- **compose 硬闸环境门 + 主线补 darwin build/vet** —— `scripts/ci/release-smoke.sh` 的 export 清单缺 `MEILI_MASTER_KEY`，而 `compose.prod.yaml` 对它有 `${VAR:?}` 硬闸、docker compose 在任何子命令之前都会先给整份文件插值，于是 smoke 连 `compose pull` 都跑不到，与是否启用 `search` profile 无关。`ci.yml` 的 `go` job 补 darwin 两架构 `go build ./...`（守发版资产）与 `go vet ./...`（守测试编译），静态线新增 `./tests/validate-release-smoke-compose-env.sh` 并挂进 `scripts/test.sh`；新门按 smoke 脚本的 `-f "$ROOT_DIR/<file>"` 取文件清单而不是硬编码文件名，并断言 `-f` 出现次数等于解析到的文件数（正例 15 处硬闸变量全满足，负例删掉 export 后 exit 1 并点名变量）。复审后又收紧了两处判据，因为它们与要防的失败模式同形：计数面必须认 `-f` / `--file` 的任何写法并进分母、解析面只认规范写法并按行逐处比对，否则把 `-f` 改写成 `--file` 会让解析数与计数一起缩水、断言恒相等而门静默变绿；`${VAR:?}` 对空串同样拒绝，所以 `export VAR=` 现在也红（含 `UNRECOGNIZED` / `EMPTY` 点名，注释掉的旧硬闸不再误红）。darwin 四条命令同时补 `CGO_ENABLED=0`，与 `build-release-assets.sh` 的发版构建同参，不依赖「交叉编译默认关 cgo」这个隐式默认。`5f39e0d2c`、`e64691324`
- **审计棘轮：picomatch 无修复版本，登记为基线例外** —— `GHSA-fc5q-39xc-vjpf`（high，CVSS 3.1 7.5，仅可用性）的上游 `first_patched_version` 为 null、registry 上最新就是 4.0.7，没有可升的修复版本；lockfile 的 21 条解析全部落在构建工具链，生产构建产物 `.output/server` 内无该模块、无代码 import。按棘轮门既有语义登记一条基线例外（44 → 45 条），不改判据、不动依赖树，复位条件见 `knowledge/decisions/2026-11-18-picomatch-redos-advisory.md`。`41923f941`

### 扩展制品完整性（#253–#256）

- **发布期 fail-closed 闸门** —— `insertPluginRuntimePublication` 在写 publication / member 两行之前，逐成员按 `extension_versions.package_path` 跑 `artifactintegrity.Verify`；任一缺陷即 abort 且一行不写。**9 个生产发布调用点全部继承**（publish / recovery / trust-revocation / quarantine / builtin-sync / authoritative-genesis），无开关、无 reason 豁免；空成员集（genesis）仍可发布。失败保留 `extensionId` / `version` / `digest` / 相对 `path` 四坐标。`0bf151841`
- **制品族失败可诊断** —— 新增 `app/Support/Extensions/ArtifactIntegrity` 作为制品族唯一坐标载体（不 import 项目内包，避免装载点与构造点成环）；制品族哨兵收敛到一个 `ErrArtifactUnusable`；装载期失败命中 `plugin_artifact_incomplete`（`/api/v1/ready` 的 `recovery.code` 与 503 body 的 `data.code`），不再落进 `pluginRuntimeRecoveryMessage` 的兜底分支。`afbc1676d`
- **插件进程识别回归** —— EX2-01 沙箱启动器把清单相对入口 `backend/plugin` 当 `argv[0]`，而采样器要求 cmdline 含 `storage/extensions/` 路径标记，于是后台显示「插件占用 0 个进程」。改为返回**绝对制品入口**，exec 目标仍是 `/proc/self/fd/3` 的已校验 inode，沙箱强度不变。`2dc013a96`
- **执行目标与 cwd 同源** —— 修 `backend/plugin` 相对路径在非 `apps/api` cwd 下启动即 ENOENT 导致的全站 503。`55f481bfb`

### 扩展执行信任链与沙箱

- **exec 前重算摘要 + 进程级加固** —— 执行前重新核对摘要，链接安装的摘要改为必填并做字段级拦截。`a288a8a0a`、`e3ebb3e29`
- **raw_core 收敛到显式白名单** —— DML 不再按 `pg_class` 快照枚举 `public` 全量 Core 表（实测 165 张），改为显式白名单 + 默认拒绝；白名单外写入在首次使用时得到 `SQLSTATE 42501`。这是对已装 `raw_core` 插件的行为变更。`d3aace358`
- **`sforum_core_v1` 补 PUBLIC REVOKE** —— 把「PUBLIC 零权限」从一次性动作变成可重复兑现的约定，并加静态棘轮：今后每个建视图的迁移必须自带 schema 级 REVOKE。只收紧权限，Down 不重新打开。`d3aace358`
- **前端信任挑战改持久化存储** —— 跨实例可校验；挑战存储故障映射为 503 而不是静默放行。`3a70e0e80`、`abb0c11bf`
- **沙箱残余** —— cgroup 迁服务 scope（`Delegate=yes` + `DelegateSubgroup=payload`）、TMPDIR 判活改按进程实例（pid + starttime + boot_id）、同插件两实例建组竞态改按 cgroup 名分片的宿主 flock。`2c84e4205`

### 身份与权限

- **deny 覆盖压过父权限展开（P1）** —— 装载代码在 deny 过滤**之后**做「父权限 → 子权限」展开，把被 deny 的子权限重新加回集合：覆盖写入成功、后台显示已保存，`Can()` 仍经父权限放行。改为用「显式 false 条目」表达 deny，展开时跳过 denied 子权限，四个装载点（含事务路径 `LoadEffectiveActorTx`）全部接入。`c382e366b`
- **角色建议批准补权限包含不变量（R8-BE-06）** —— 批准主路径与 legacy 显式 apply 分支各要求「批准者已持有该权限」，判定留在 SQL（新增参数化函数 `extension_identity_actor_holds_permission`，与 trigger 用的函数逐字同构），驳回路径不调用。与已修的建号铸权、改角色权限同构的横向提权一并收口。`71d45e97e`
- **角色模板收敛为单一权威源** —— `seeds.go` 的 `SeedRoleTemplates` 成为唯一源，`apps/web/app/config/roleTemplates.ts` 降为生成物；同时收敛库侧权限包（operator 得 `moderation.manage` / `trust.manage` / `entity_meta.manage` / `attachment.upload_policy.manage`，`tech_admin` 得 `ai.manage`）。`d4c2c91e6`、`5ad5de84d`
- **`can()` 退化为查表** —— 前端只消费后端已展开、已扣除的权限集，不再自己重做父权限推导。`f3e95d837`
- **后台可管理门与菜单候选去掉父键** —— 只认细粒度子键，`extension.manage` 不再单独当导航准入。`f499325f7`、`c37afb6a8`

### 登录、PAT 与强制下线

- **登录豁免不再跳过失败锁定** —— `SkipHumanVerification` 原本短路在失败锁定判定**之前**，于是携带 `issueApiToken` 的登录请求可跳过全部触发条件（含账号失败阈值）。失败锁定判定前移，豁免只覆盖其后的策略类触发条件（always / new_device / privileged）。`39fb04e3e`
- **登录锁定计数改 Lua 原子** —— 并自愈无 TTL 的残留键；PTTL 证据不再静默 skip。`191c4e441`、`56da3585d`
- **失败锁定读失败只降级 lockout 分支** —— 不再放弃整条策略链；`new_device` / `privileged` 两条降级分支补测试。`540637064`、`bc43e62ed`
- **PAT 纳入 `token_version` 失效** —— 强制下线与改密都只递增 `users.current_token_version` 并撤 `user_sessions`，`api_tokens` 完全不受约束：拿到 PAT 的机器客户端在「下线全部设备」之后仍能继续访问。新增迁移把每条 PAT 记录签发时的用户版本落库，鉴权时比对，不一致即失效；`revoke_reason` 与 `user_sessions` 同口径（`admin_revoke` / `password_reset` / 自助撤销）。`65787967f`
- **PAT 其余收口** —— 创建加行锁（`INSERT ... SELECT current_token_version` 一条语句取版本）、`RestrictActor` 保留 deny 的显式 false 条目、`last_used_at` 写入加 1 分钟节流。`0db6c3888`、`fcdc86eda`、`c0ab8d80d`、`7218be6c6`
- **ALTCHA replay 键去掉 purpose** —— 防跨场景复用；兼容分支留档决策。`5e472aca0`、`22b5332bd`

### 部署与运维

- **一键入口不再静默退出 2（R8-OPS-01）** —— `sforum-latest.sh` 对缺失的 `.deployrc` 跑 `sed`，在 `set -euo pipefail` 下成为致命失败，且失败点早于 ACTION 分派：`--check` / `install` / `repair` 三条分支全部不可达，只打印「安装目录」就 `EXIT=2` 且 stderr 为空。改为 `-f` 判定 + 「存在但不可读」明确 `die`，真实读错误不再被吞成空版本。`87c9810e8`
- **三把互不相认的锁收敛到 `.deploy.lock`（R8-OPS-02 + R8-OPS-05）** —— `sforum-bootstrap.sh` 的 `promote_bundle` 只受自己的 `.sforum-bootstrap.lock` 保护，升级窗口内仍可把 `deploy.sh` / `upgrade.sh` / 四个 compose / `deploy-lock.sh` 逐文件覆盖。改为同域 `.deploy.lock`（活锁拒绝、死 pid 回收、`--unlock` 只回收陈旧锁），加锁只覆盖 `promote_bundle`，下载与校验在锁外。`8ba9b6f5f`

## 升级注意

> 以下按「必须动作 / 行为变更 / 回滚风险」三类列出。**回滚风险三项（第 11–13 项）换二进制前必读。**

1. **必须执行迁移（7 个）** —— 6 个标注 `+sforum OnlineSafe`，可在线应用，不需要停机窗口；`202611160001` 是「加列 + 一次性回填」，只扫 `api_tokens` 一张表。`upgrade.sh` / `sforum-bootstrap.sh upgrade` 与 `sforum-migrate` 镜像会正常带出；手工部署请**先跑迁移再切 API 镜像**（新函数的注释写明这条部署顺序）。
2. **必须确认生产环境变量** —— `compose.prod.yaml` 新加 `POSTGRES_PASSWORD` / `REDIS_PASSWORD` / `MEILI_MASTER_KEY` 三处 `${VAR:?}` 硬闸，加上既有的 `SESSION_HASH_SECRET` / `IDENTITY_SUBJECT_HMAC_SECRET` / `APP_OPTION_ENC_KEY` / `ALTCHA_SECRET`。`deploy.sh` / `upgrade.sh` 会对存量安装做 env backfill；**手工 `docker compose up -d` 的部署必须自己补齐**，否则直接报缺项。`4b4352d48`
3. **必须重启 API 让 8 个内置插件抬版生效** —— 重启后 `SyncBuiltins` 把新 digest 标为 staged，后台按既有三态显示「可升级 v{staged}」/「重启后生效」/「激活后生效」；要真正生效需在后台激活。`450b794eb`
4. **行为变更：明文恢复源默认拒绝** —— 归档 / SQL 载荷缺完整性清单时默认失败，需显式 `SFORUM_RESTORE_ALLOW_UNVERIFIED=1` 才继续（会打警告）。依赖「随便丢一个 `.sql` 就能恢复」的脚本必须改。`918404431`
5. **行为变更：备份 v2 且 `upgrade.sh` 有前置形态检查** —— 本版产出的备份是 encrypt-then-MAC 信封，v1 旧归档仍可读并打降级告警；`upgrade.sh` 跑 `--check-online-safe` 预检，迁移形态畸形即 exit 3 直接 abort。`4b4352d48`、`ba212257b`
6. **行为变更：三把锁合成一把，一键入口退出码语义变了** —— 所有部署入口共用 `.deploy.lock`（活锁拒绝、死 pid 回收、`--unlock` 只回收陈旧锁）；`sforum-latest.sh` 在缺 `.deployrc` 时不再静默 `EXIT=2`，改为非 0 且 stderr 带 `sforum-latest: ` 前缀。按退出码 2 做分支的外部脚本需要复核。`8ba9b6f5f`、`87c9810e8`
7. **行为变更：`deploy.sh` 拒绝在蓝绿拓扑上跑** —— 蓝绿安装必须走 `upgrade.sh`；恢复流程在无应用槽时不再删旧库。`4b4352d48`、`dedff7993`
8. **行为变更：`POST /admin/extensions/{id}/settings/reset` 已下线** —— 路由目录 437 → 436；「恢复默认」请用 `PUT /admin/extensions/{id}/settings` 提交推荐值。`723561e9b`
9. **行为变更：`sforum_core_v1` 的 PUBLIC 权限被收回** —— 若曾手工给 `PUBLIC` 授过该 schema 的权限，本版会收回；新视图迁移必须自带 schema 级 REVOKE（静态棘轮会拦）。`d3aace358`
10. **行为变更：`raw_core` 写入面收敛 + 默认主题启动自愈** —— 已装 `raw_core` 插件访问白名单外的 `public` 表，首次使用时得到 `SQLSTATE 42501`（此前依赖 `pg_class` 快照口径）；默认主题账本丢了 host 批准时，启动会补一版 `reason=startup_repair` 的批准（幂等、健康时零写入，且只在 `ActorUserID == 0` 时按 host 批准落地）。`d3aace358`、`2dc013a96`
11. **回滚风险：PAT 的 `token_version`** —— 回退到旧二进制后它不读该列，强制下线 / 改密对机器客户端重新失效不了（安全回退，不报错）；`goose down` 会删掉 `revoke_reason` 与 `token_version` 两列，撤销原因随之丢失。**回退二进制与回退迁移是两件事，别把 down 当清理手段。** `65787967f`
12. **回滚风险：备份与恢复是单向的** —— v2 归档只有本版脚本能验；用旧版发布资产去恢复本版产出的备份会失败（v1 兼容是「新读旧」，不是「旧读新」）。同时混版窗口里旧 `sforum-bootstrap.sh` 仍用 `.sforum-bootstrap.lock`，与 `.deploy.lock` 不互斥，升级窗口内的文件覆盖保护会短暂失效。`4b4352d48`、`8ba9b6f5f`
13. **回滚风险：`202611170001` 的新函数纯增量，但顺序不能反** —— 迁移只新增函数、不改老函数与 trigger，回退二进制后函数留存而无害；反过来「先 down 迁移、仍跑新二进制」会让角色建议批准路径找不到函数而失败。迁移回滚必须**先于**二进制回滚。`71d45e97e`
14. **不需要动作，但要知道：`pluginprocess.Limit` 在非 Linux 上是显式 no-op，主线新增两条门** —— darwin/*BSD 没有 `prlimit(2)`，`Limit` 在那里不施加任何 rlimit；这些平台本来就没有可用制品，因此这是**新增的能力边界说明**，不是行为变更。加固不会降级成 `setrlimit`：fork 之后父进程调它只改宿主自己，插件子进程一个字节都不受影响，用「改宿主」顶替「改插件」会把缺口伪装成已完成。同时主线新增两条门——darwin 两架构 build + vet、compose 硬闸环境门——「改 compose 的 `${VAR:?}` 却不补 smoke 环境」与「darwin 测试引用 Linux-only 的 `unix.Prlimit`」都会在 `main` 上当场红，而不是等到发版。`23fad3e3b`、`5f39e0d2c`
