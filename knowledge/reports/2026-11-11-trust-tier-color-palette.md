# 信任等级档位：8 色语义色板与对比度核验

日期：2026-11-11
状态：取值表 + 对比度实测已定稿（可直接落地）；风格建议在文末，属后补项。
范围：本文只给设计取值与核验，不改代码。落地写入点由前端负责。

## 0. 结论先行

- 8 个 token（slate, teal, emerald, sky, indigo, violet, rose, amber）已冻结，本文不改名、不增删，按 rank 顺序使用，TL0 = slate。
- 所有取值在四项核验上**全部达标**：徽章文字压在卡片底 ≥ 4.5:1、压在 12% 混色底 ≥ 4.5:1、3px 色条 ≥ 3:1、深色实心块内 `#18181b` 文字 ≥ 4.5:1。
- 最薄的两处余量：浅色 `teal` 在 12% 混色底上 **4.64:1**、深色 `indigo` 在 12% 混色底上 **5.00:1**（公开页深色底 `#1b201f` 上降到 **4.63:1**）。仍在线内，但不要再往浅/往亮调。
- 与建议初稿的偏离（均为对比度驱动，非审美偏好）：
  - `amber` 浅色从 amber-700 `#b45309` 退到 **amber-800 `#92400e`**：700 级在 12% 混色底上只有 **4.25:1**，差 0.25 不达标（600 级更差，2.81:1）。
  - `teal`/`emerald` 浅色不能用 600 级：`#0d9488`/`#059669` 在混色底上都是 **3.25:1**。取值退到 700 级后 teal 用 `#0f766e`，emerald 用 green-800 `#166534`。
  - `emerald` 明确取**更偏绿**的 143° 色相而非 Tailwind emerald 的 160°，为的是与相邻 `teal`(175°) 拉开到 32°——这是 8 色里最容易糊在一起的一对。
  - `rose` 取 `#be185d` / `#f472b6`（偏冷的粉，335°/329°），避开站点 rose 主题的 accent `#e11d48` / `#fb7185`（347°/351°）。

## 2. 对比度核验

### 2.1 方法与算式

WCAG 2.1 相对亮度：

```
c_lin = c/12.92                     (c <= 0.04045)
c_lin = ((c+0.055)/1.055)^2.4       (c > 0.04045)
L = 0.2126*R_lin + 0.7152*G_lin + 0.0722*B_lin
contrast = (L_light + 0.05) / (L_dark + 0.05)
```

12% 混色底按 `color-mix(in srgb, <token> 12%, <card>)` 的 sRGB 通道线性插值计算（即 `0.12*token + 0.88*card`），与该 CSS 函数的实际行为一致；透明叠加同理按 alpha 合成。

计算脚本（Python 3，无第三方依赖，结果可复现）：

```python
def rgb(h):
    h = h.strip().lstrip('#')
    if len(h) == 3: h = ''.join(c*2 for c in h)
    return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))

def lin(c):
    c /= 255
    return c/12.92 if c <= 0.04045 else ((c+0.055)/1.055)**2.4

def lum(h):
    r, g, b = [lin(x) for x in rgb(h)]
    return 0.2126*r + 0.7152*g + 0.0722*b

def cr(a, b):
    x, y = lum(a), lum(b)
    hi, lo = max(x, y), min(x, y)
    return (hi + 0.05) / (lo + 0.05)

def mix(fg, bg, p):   # color-mix(in srgb, fg p, bg)
    f, b = rgb(fg), rgb(bg)
    return '#' + ''.join('%02x' % round(f[i]*p + b[i]*(1-p)) for i in range(3))
```

## 3. 相邻可辨性（默认色序）

色相取 HLS 的 H，明度取 WCAG 相对亮度 L，非感知均匀空间，只作相对参考。

### 3.1 浅色

| 相邻对 | ΔHue | ΔL | 判断 |
|---|---|---|---|
| slate → teal | 40° | 0.053 | 可辨。中性→彩色本来就是最强的"起点"信号 |
| teal → emerald | 32° | 0.045 | 可辨，但是本套最接近的一对青绿。已把 emerald 从 160° 推到 143°；再近就会有风险，不要回退 |
| emerald → sky | 58° | 0.030 | 可辨，靠色相不靠明度 |
| sky → indigo | 44° | 0.044 | 可辨 |
| indigo → violet | 17° | 0.051 | 靠明度差撑住。18px 以下小圆点会显得像"同一个紫的深浅"，必须始终显示 TL 序号文字 |
| violet → rose | 73° | 0.026 | 可辨，色相差足够 |
| rose → amber | 48° | 0.026 | 可辨，粉 vs 金没有歧义 |

### 3.2 深色

| 相邻对 | ΔHue | ΔL | 判断 |
|---|---|---|---|
| slate → teal | 43° | 0.155 | 强可辨 |
| teal → emerald | 30° | 0.039 | 可辨。深色下两者都高饱和，是最需要小心的一对；12px 色条 OK，8px 以下圆点建议加白色描边或只用作色条 |
| emerald → sky | 56° | 0.112 | 强可辨 |
| sky → indigo | 36° | 0.138 | 强可辨 |
| indigo → violet | 21° | 0.034 | 深色下最容易看混的一对之一（蓝紫相邻）。同样靠 TL 序号文字兜底 |
| violet → rose | 74° | 0.011 | 明度几乎相同，全靠色相；74° 足够，但不要在小尺寸下把它俩放在同一行做并排对比 |
| rose → amber | 74° | 0.233 | 强可辨 |

结论：深色模式没有必须改的取值；两处"最容易被看成同色"是 `teal↔emerald` 与 `indigo↔violet`。缓解手段按性价比排序：始终渲染 `TL{n}` 文本（0 成本）> 8px 元素加 1px 描边 > 改色（会破坏已通过的对比度矩阵，不建议）。

## 4. 与站点主题解耦

站点主题在 `apps/web/app/assets/css/main.css` 里以 `html[data-sforum-theme="..."] { --sf-accent: ... }` 形式给出五套 accent（teal / ocean_blue / violet / rose / amber）。新的 `--sf-tl-*` 定义在 `:root` 与 `.dark` 上，二者互不引用：主题切换只改 `--sf-accent*`，`--sf-tl-*` 保持原值。因此档位色**不会跟随主题漂移**，同一个 TL 数字在五个主题下颜色恒定——这是有意的：档位是权限语义，不应随外观变化。

唯一的真实冲突点是 `rose` 档位与 rose 主题：

- 浅色：主题 accent `#e11d48`（347°）vs 档位 `#be185d`（335°），色相差 12°，两者亮度比 1.29。
- 深色：主题 `--sf-accent-dark` 是 `#fb7185`（351°）vs 档位 `#f472b6`（329°），色相差 22°，亮度比 1.02（几乎同亮度，只靠色相）。

判断：可接受但不宽裕。理由与处理原则：

1. 档位色只以两种形态出现——3px 左侧色条、12% 淡底徽章；主题 accent 只用在按钮、链接、选中态这类实心/前景元素上。两者在版面上不相邻，不会形成"同色不同义"的对照。
2. 若视觉走查仍认为会误读，**优先改几何不改色相**：rose 主题下把档位色条降为中性（`--sf-tl-rose: var(--sf-border-strong)`），只保留 TL6 文字。这样零风险、不需要新 hex、也不会引入第二套对比度结论。
3. 需要保留彩色时的可选覆盖（已实测通过，但会改变 rose 的语义观感，默认不启用）：rose 主题下档位 rose 移到品红 `#a21caf`（浅色，卡片 6.32 / 混色底 5.20，295°）、`#e879f9`（深色，7.20 / 5.94，292°）。这两个值在 rose 主题下不会被误认为 accent，但"rose 档显示成品红"需要产品确认。

对应的可选覆盖块（默认注释掉，不进主干）：

```css
/* 仅在视觉走查判定 rose 档与 rose 主题 accent 混淆时启用 */
/*
html[data-sforum-theme="rose"] { --sf-tl-rose: #a21caf; }
html[data-sforum-theme="rose"].dark { --sf-tl-rose: #e879f9; }
*/
```

`teal` 档位与 teal 主题 accent（默认主题，`--sf-accent` 为青绿系）同理存在同族不同深的问题，但 teal 主题的 accent 与 `#0f766e`/`#2dd4bf` 明度差明显，且默认主题下"档位即配色"读起来是舒适而非歧义，不作处理。

## 5. 停用态

已停用行：色条 45% 不透明度 + 虚线边框。合成后的实测值（色条压在卡片上）：

| token | 浅色 45% | 对比卡片 | 深色 45% | 对比卡片 |
|---|---|---|---|---|
| slate | `#acb2bc` | 2.13 | `#505762` | 2.43 |
| teal | `#93c1be` | 1.98 | `#216d65` | 2.90 |
| emerald | `#96baa4` | 2.13 | `#2f7148` | 3.02 |
| sky | `#8ebcd5` | 2.04 | `#26627e` | 2.64 |
| indigo | `#aaa5e7` | 2.27 | `#474c7e` | 2.20 |
| violet | `#bd9eee` | 2.07 | `#584c7f` | 2.32 |
| rose | `#e297b6` | 2.25 | `#7b4061` | 2.32 |
| amber | `#cea993` | 2.16 | `#7e631f` | 3.11 |

判断与建议：

- 45% 在浅色下是 1.98–2.27:1，深色下 2.20–3.11:1。WCAG 1.4.11 对"已禁用组件"不作对比度要求，所以这里不构成合规问题；要求是"仍可辨"。浅色 `teal` 的 1.98 是本套最淡的一处，在 `#ffffff` 上作为 3px 竖直条仍可见（宽度 3px 是它的第二重线索），可以接受。
- 若走查认为浅色偏虚，把停用态提到 **55%**（浅色 2.34–2.78、深色 2.69–4.05）即可，仍是明显的"降权"观感。
- 深色建议**默认就用 55%**：暗底吃掉饱和度，45% 的 `indigo`/`violet`/`rose` 只有 2.20–2.32:1，和浅色 45% 的观感不对等。两者取 55% 后深浅观感才齐平。
- 停用态不要同时降低徽章文字的不透明度：文字继续用 `--tl-ink` 全值，仅色条与底色降权，否则 TL 序号会掉到 4.5:1 以下。

## 6. 可直接粘贴的 CSS

```css
/* 信任等级档位色。顺序 = rank，TL0 = slate。取值经 WCAG 实测，见
   knowledge/reports/2026-11-11-trust-tier-color-palette.md */
:root {
  --sf-tl-slate: #475569;
  --sf-tl-teal: #0f766e;
  --sf-tl-emerald: #166534;
  --sf-tl-sky: #0369a1;
  --sf-tl-indigo: #4338ca;
  --sf-tl-violet: #7c3aed;
  --sf-tl-rose: #be185d;
  --sf-tl-amber: #92400e;
}

.dark {
  --sf-tl-slate: #94a3b8;
  --sf-tl-teal: #2dd4bf;
  --sf-tl-emerald: #4ade80;
  --sf-tl-sky: #38bdf8;
  --sf-tl-indigo: #818cf8;
  --sf-tl-violet: #a78bfa;
  --sf-tl-rose: #f472b6;
  --sf-tl-amber: #fbbf24;
}
```

档位行与前台信任卡共用的派生阶梯（可选，随行内 `--tl-accent` 一起用）：

```css
.sf-tl-accent {
  /* 行内 style 覆盖成对应 token，例如 style="--tl-accent: var(--sf-tl-emerald)" */
  --tl-accent: var(--sf-tl-slate);
  --tl-ink: var(--tl-accent);
  --tl-soft: color-mix(in srgb, var(--tl-accent) 12%, var(--sf-card));
  --tl-soft-border: color-mix(in srgb, var(--tl-accent) 26%, var(--sf-card));
  --tl-bar: var(--tl-accent);
}

.sf-tl-accent[data-tier-state="disabled"] {
  --tl-soft: color-mix(in srgb, var(--tl-accent) 6%, var(--sf-card));
  --tl-bar: color-mix(in srgb, var(--tl-accent) 45%, var(--sf-card));
  --tl-border-style: dashed;
}

.dark .sf-tl-accent[data-tier-state="disabled"] {
  --tl-bar: color-mix(in srgb, var(--tl-accent) 55%, var(--sf-card));
}
```

落地注意：

- `--sf-card` 在前台解析为 `--sf-public-surface`（浅色 `#ffffff` / 深色 `#1b201f`），2.4 节已按该底色复核过，不需要第二套 token。
- `color-mix()` 需要 Chromium 111+/Safari 16.2+/Firefox 113+。低于此的环境请先给 `--tl-soft` / `--tl-bar` 写静态 fallback（`var(--sf-surface-muted)` / `var(--tl-accent)`），再写 `color-mix()`；不要用 `@supports` 包整个规则块，否则新浏览器会丢行内变量的继承链。
- 徽章边框用 26% 混色（实测与 12% 底的可辨识比 1.2–1.4:1，仅作边缘勾勒；不要指望它承担 3:1 的边界职责，那条职责由色条承担）。
- 运营单档覆盖只改 `--tl-accent`（行内），不要改 `--sf-tl-*`；`--sf-tl-*` 是默认色序的唯一来源。

## 7. 风格说明（后补项）

- 整体走向：cold → warm 的单向渐变，`slate` 无彩作起点、`amber` 唯一暖色作终点。等级越高越"亮"，在深色模式里表现尤其直观（L 从 0.36 递增到 0.58），这也是深色下 `rose→amber` 观感最强的档位跃迁。
- 浅色下我刻意让明度不做单调递增：`indigo`(0.083) 最重、`teal`(0.142) 相对最浅。因为浅色底上彩色本身已经足够区分，再叠明度阶梯会让低档位显得"褪色"，反而弱化可读性。明度阶梯留给深色模式承担。
- 徽章用 12% 淡底 + 100% 文字、色条用 100%：同一个 token 的两种强度，比"实心徽章 + 白字"更省视觉注意力，也避免 8 个实心色块把整页压垮。
- 不为档位引入渐变、发光、描边阴影或角标；区分只靠色相 + 序号文字。档位是权限语义，装饰多一分，误读风险多一分。

## 8. 未验证/边界

- 未做真机/浏览器渲染截图核验：本文全部数字来自 sRGB 的数学计算，不是取色器读数。若浏览器对 `color-mix()` 的取整策略与本文的线性插值差 1 个色阶，比值变动在 0.02 以内，不改变任何达标结论。
- 未覆盖 OLED 高对比度、`forced-colors` 模式与印刷场景。`forced-colors: active` 下浏览器会强制替换颜色，色条会退化为系统色，这属于预期行为，不做补偿。
- 相邻档位判断基于色相与相对亮度两个标量，没有算 CIEDE2000；若后续要做严格的感知距离验收，需要在同一套 hex 上重算 ΔE00 并给出阈值。

## 9. 9 色版：新增 `fuchsia`（插在 violet 与 rose 之间）

### 9.1 为什么必须扩

`MaxTiers=8`，而 `slate` 被 TL0（未达标起点）占用，rank 1..8 需要 8 个非 slate 的 token，原 8 色只提供 7 个：满配时 TL8 会回落到 slate，与 TL0 同色，等于"最高权限"和"最低起点"视觉上完全一致。这是功能性缺陷，不是配色偏好。

新序列（rank = index，TL0 = slate）：

```
slate(TL0) -> teal(TL1) -> emerald(TL2) -> sky(TL3) -> indigo(TL4) -> violet(TL5) -> fuchsia(TL6) -> rose(TL7) -> amber(TL8)
```

`amber` 仍是唯一暖色与终点，语义不变。

### 9.2 `fuchsia` 取值

沿用第 1 节 rose 的备选值，直接通过全部核验，不需要替代值：

| token | rank | 浅色 hex | 深色 hex | 用途说明 |
|---|---|---|---|---|
| fuchsia | TL6 | `#a21caf` | `#e879f9` | 高权限档，紫与粉之间的品红，把 violet 与 rose 之间的空档补上 |

偏离说明：浅色 `fuchsia-600 #c026d3` 不达标（压混色底 3.93:1），退到 700 级 `#a21caf`；深色 `fuchsia-400 #e879f9` 一次通过，无需调整。

### 9.3 对比度核验（同一套矩阵）

| 核验项 | 浅色 `#a21caf` | 深色 `#e879f9` | 目标 |
|---|---|---|---|
| 压在 `--sf-card`（`#ffffff` / `#18181b`） | **6.32** | **7.20** | ≥ 4.5 通过 |
| 压在 12% 混色底 | `#f4e4f5` → **5.20** | `#312436` → **5.94** | ≥ 4.5 通过 |
| 3px 色条（非文本） | **6.32** | **7.20** | ≥ 3.0 通过 |
| 深色实心块内 `#18181b` 文字 / 浅色实心块内 `#ffffff` 文字 | 6.32 | 7.20 | ≥ 4.5 通过 |
| 公开页深色底 `#1b201f` | 不适用（浅色页底为 `#ffffff`） | 卡片 **6.70** / 混色底 `#342b39` **5.50** | ≥ 4.5 通过 |

被否掉的候选：`#c026d3`（卡片 4.71 / 混色底 3.93）、`#e879f9` 用作浅色前景只有 2.46，均不可行。

### 9.4 相邻可辨性

| 相邻对 | 浅色 ΔHue / ΔL | 深色 ΔHue / ΔL | 判断 |
|---|---|---|---|
| violet(262°) → fuchsia | 33° / 0.018 | 37° / 0.041 | 可辨。深色下是本链第二弱的一对（仅次于 indigo↔violet 的 21°），由 TL 序号文字兜底 |
| fuchsia → rose(335°) | 40° / 0.008 | 37° / 0.030 | 可辨。浅色下明度几乎相同（ΔL 0.008），全靠 40° 色相；12px 以下小圆点上两者偏接近，3px 色条与徽章形态下无问题 |

加入 fuchsia 后，9 色链最弱的三对依次是：`indigo↔violet`（21°/0.034 深色）→ `violet↔fuchsia`（37°/0.041 深色）→ `teal↔emerald`（30°/0.039 深色）。这三处都在 30° 以上或由明度差分担，结论：不需要再调色；缓解手段仍是始终渲染 `TL{n}` 文本。

### 9.5 与站点主题的冲突复核

- fuchsia 不是任何主题的 accent：与 rose 主题 accent `#e11d48`（347°）差 52°、深色 `#fb7185`（351°）差 59°，亮度比 1.35 / 1.09。**不撞**，不需要覆盖。
- 顺带发现两处原有的完全同色（本轮实测，非本次新增的问题，供后续决定是否处理）：`violet` 档位浅色 `#7c3aed` 与 violet 主题 `--sf-accent` 完全一致（比值 1.00），深色 `#a78bfa` 与 `--sf-accent-dark` 也完全一致；`amber` 档位深色 `#fbbf24` 与 amber 主题 `--sf-accent-dark` 完全一致。影响有限——档位色只以 3px 色条与 12% 淡底出现，主题 accent 用在按钮与链接上，两者不并置；但若某天走查认为"紫主题下 TL5 看起来像按钮"，处理方式与第 4 节 rose 相同：优先改几何与形态，不改色相。

### 9.7 停用态补充
