# 2026-11-18 v3.1.5 发版（文档 CSP 全站下发）

## Changed

- 文档 CSP 基线改为「宿主文档可满足的来源白名单」：`style-src 'self' 'unsafe-inline'`、
  `img-src 'self' blob: data: https:`、`script-src 'self' 'nonce-…'`；`script-src`/`worker-src`
  代码边界未动。
- 收窄 `publicPageDocumentPolicy()` 的合并后断言：可执行指令只约束**扩展片段**，
  宿主基线不再被「必须恰好 `['self']`」拒绝（否则策略端点 500、静默不写头）。
- 文档 CSP 从「有 L2 岛的页才发」改为**所有公开页无条件下发**；零 ref 走模块级缓存的
  Host 基线（in-flight 去重、失败不缓存、HMR 失效）；per-page 失败回退基线。
- 删掉 dev 短路：dev 与生产同一份 CSP，仅 dev 追加 Vite HMR websocket 与 Iconify 兜底主机。
- 新增 `apps/web/app/plugins/icon-local-provider.client.ts`：图标默认 provider 指向同源
  `/api/_nuxt_icon`，消除客户端对公共 Iconify API 的请求（生产回归修复）。
- 新增门禁 `tests/validate-document-csp.mjs`（真实 Chrome + CDP），`--self-test` 进
  `scripts/test.sh` static 线且必须通过。
- 契约与文档：`contracts/openapi/{paths/extensions.yaml,schemas/extensions.yaml,paths/pages.yaml}`、
  `knowledge/decisions/2026-11-18-public-document-csp-host-compatible.md`、
  `knowledge/reports/2026-11-18-v3.1.5-release-notes.md`。

## Decisions

- `style-src` 必须 `'unsafe-inline'`：Vue `:style` 属性在规范上无法携带 nonce/hash。
- `script-src` 保持严格，用 per-request nonce 放行宿主内联脚本；**不得**用 `'unsafe-inline'`。
- `style-src` **永不加** nonce/hash：CSP3 下同指令出现 nonce 会让 `'unsafe-inline'` 失效。
- `img-src` 允许 `https:`：CSP 管代码来源，不管内容图片；放弃项（跟踪像素、暴露访问者 IP）
  已写进决策记录 §7。
- 门禁的 nonce 必须取**同一次导航**的响应头；304/无头时走 cache-bypass 并把 nonce 比对
  降级为标注，不冒充通过。
