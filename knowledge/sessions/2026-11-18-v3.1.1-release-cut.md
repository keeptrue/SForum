## Decisions

- **失败根因两条，都在「校验只存在于 release workflow」这一点上**：① darwin 交叉编译从未在
  `main` 上跑过（`go build` 不编译 `_test.go`，build 与 vet 各守一半）；② compose 的
  `${VAR:?}` 硬闸只在 smoke job 里被插值阶段撞到。都不是「代码新错」，而是门上缺了一半。
- **compose 门按解析而不是清单**：不硬编码 compose 文件名，改从 smoke 脚本的
  `-f "$ROOT_DIR/<file>"` 取；计数与解析不一致即红。判据只收紧，不放松。
- **picomatch 登记而不是升级**：`first_patched_version = null`，升级只换版本号而不消除
  advisory；可达性有实证。裁决与复位条件见 `decisions/2026-11-18-picomatch-redos-advisory.md`。
- **非 Linux 的 `Limit` 保持显式 no-op**：darwin/*BSD 没有 `prlimit(2)`，`setrlimit` 只改
  宿主自己、改不到已 fork 的插件子进程，用它顶替会把加固缺口伪装成已完成。
- **硬闸守卫的识别面必须宽于解析面，两者按出现次数比对**；且 `export VAR` 不等于有值，判空
  必须按运行时语义（行尾空白与裸 export 都会静默变绿，取值后右裁尾部再判空）。
