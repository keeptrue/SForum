# Decision: 不为 GO-2026-5932（`x/crypto/openpgp`）升级依赖

## Status

Accepted（2026-11-16，第 15 轮 W6 裁决，W8 归档）。本条不修代码，只固化「为什么
不动」与四条复位条件——审查方指出这条此前只活在会话记录里，仓库内没有任何落地物。

## Context

- **advisory**：GO-2026-5932，命中 `golang.org/x/crypto/openpgp`。
- **当前钉版**：`golang.org/x/crypto v0.58.0`（`apps/api/go.mod:36`）；两个内置插件
  模块（`sforum-web-push`、`sforum-content-policy`）以 `// indirect` 同版本跟随。
- **扫描现状**：`.github/workflows/security.yml` 的 govulncheck 只对**可达**漏洞失败
  （`go-package: ./...`，工具链 = `go.mod` = Dockerfile = `1.26.11`）。这条一直是
  module-level finding，从未被判成 called。
- **为什么不能「顺手升掉」**：在没有修复版本的前提下，升级只是换一个 x/crypto 版本而
  不消除 advisory；而 x/crypto 正是 argon2 的实现来源，为一个零调用的包改密码哈希依赖，
  换来的是真实的回归面（哈希格式与参数、autocert 行为）。风险方向相反。
- **为什么不能「关掉扫描」**：`continue-on-error`、模块排除、降级扫描器都会把「可达漏洞
  为零」这个唯一有效信号一起关掉。审计已把这类做法记为不可接受。

## Decision

**不升级 `golang.org/x/crypto`，保留这条 module-level finding。** 三条实证：

1. **依赖图零命中**。`apps/api` 的 `go list -deps ./...` 共 **844** 个包，
   `openpgp` 命中 **0**；内置插件模块（以 `sforum-web-push` 为样本）共 **406** 个包，
   命中同样为 **0**。
2. **第一方代码只用 argon2**。全仓 `grep -rn '"golang.org/x/crypto'`（`--include=*.go`）
   只有一处：`apps/api/app/Models/Identity/password.go:13` 的 `argon2`。依赖图里其余
   x/crypto 包都是传递依赖：`acme` / `acme/autocert`（HTTP 客户端链）、`blake2b`
   （argon2 内部使用）、`pbkdf2`（`altcha-lib-go`）、`scrypt`。
3. **该 advisory 没有修复版本**（W6 的核对结论）。因此「升级到修复版」这个选项当前
   不存在。

**核对边界（诚实标注）**：本文件写就时本机无外网，`govulncheck` 取
`https://vuln.go.dev/index/modules.json.gz` 直接 EOF，无法二次抓取 advisory 的
`fixed` 版本字段。第 1、2 条是本文件实测（命令见下）；第 3 条沿用 W6 的核对结果，
并由复位条件 2 兜住——一旦上游出现修复版本，这条决策就必须重开。

## 复位条件（满足任一条就重开本条，不要沿用「零调用」的结论）

1. **依赖图出现 openpgp**：任何受管模块的 `go list -deps ./...` 命中
   `golang.org/x/crypto/openpgp`（新依赖、插件 SDK、工具链升级都算），或第一方代码
   import 该包。
2. **上游出现修复版本**：x/crypto 发布包含该 advisory 修复的版本，且升级后
   `govulncheck ./...` 不新增可达漏洞。升级后把本条改成「已修复」并记录版本。
3. **扫描口径变化**：`govulncheck` 把它判成 called/reachable，或 Security 门从「只报
   可达」改成「module 级也 fail-closed」。此时「零调用」不再能作为豁免理由。
4. **产品需要 OpenPGP**：出现签名 / 验签 / 公钥导入等真实调用面（邮件签名、制品签名、
   导入第三方公钥都算）。零调用的前提消失，先评估替代实现或把该能力隔离到独立进程 /
   独立模块，再谈主模块依赖。

## Consequences

- Security 工作流会继续出现这一条 module-level finding，而 `reachable = 0` 不变。它是
  已知项，不是回归；不要用 `continue-on-error`、模块排除或降级扫描器去「修」它。
- 任何因其它原因升级 x/crypto 的改动，都要重跑本节的三条实证；任一条不成立就按复位
  条件处理，而不是照抄结论。
- 审计总表「未闭环」里的这一条从「待修」改为「已裁决（不修 + 复位条件）」，不再计入
  待办分母。

## 复核命令

```sh
cd apps/api && go list -deps ./... | grep -ci openpgp        # 期望 0
cd apps/api && go list -deps ./... | wc -l                    # 844（包数，随依赖变化）
cd extensions/builtin/plugins/sforum-web-push/backend \
  && go list -deps ./... | grep -ci openpgp                   # 期望 0
grep -rn '"golang.org/x/crypto' --include=*.go apps/api extensions \
  | grep -v node_modules                                      # 只有 argon2 一处
```
