## 问题

`trust.levels` 的 `limits` 从 N 档改造起一直是**只读**：前端原样带回，后端接受，
但运营没有任何入口按档调「发主题冷却 / 回复冷却 / 每日主题上限 / 每日回复上限」。
想让「TL3 以上免冷却」「TL5 每天 20 帖」只能改代码发版——而这正是等级体系最常用的运营动作。

难点不在表单，而在**三态语义不能被 UI 抹平**：`null`（继承站点默认）、对象（逐字段覆盖，
某个字段为 `null` = 该字段仍继承）、`0`（不限额 / 免冷却）是三种不同的存储值，
其中 `0` 与「没配」严格区分。任何把它简化成「开关 + 数字框」的做法都会把「不限额」
变成「继承」。

## 决定 D-L1：三态就是后端的三种输入，不发明第四种

**裁决**：第 5 个分区只有三种状态，与 `config.go` 的解码输入一一对应：

- **继承**：该档 `limits = null`，四个输入原生 `disabled`，显示「跟随站点默认」；
- **逐字段覆盖**：`limits = { … }`，留空的字段仍写 `null`（= 该字段继续继承）；
- **`0`**：明确的不限额 / 免冷却，payload 里就是 `0`，与空串（继承）在 UI 上可区分。

「字段省略」（`len(raw) == 0`）是后端会 422 的第四种输入；前端**永不写出**它：
`trustLevelsPayload` 的 `limits` 恒存在，只输出 `null` 或四键对象（`useTrustLevelsForm.ts:675-708`，
本刀未改该函数）。

**理由**：三态不是 UI 风格选择，是存储形状。前端多发明一种状态，它最终必须落回这三者之一，
于是「运营看到的」和「保存下去的」之间多一层翻译，而这种翻译只在保存失败时才暴露。
纯函数层 `useTrustLevelLimits.ts` 把语义写死成 `inherit | custom` 两模式 + 每字段三值，
`parseLimitInput` 先 `trim` 判空再走 `/^\d+$/`，空串永不经 `Number()` 变成 `0`。

**被否**：为 UI 发明第四种状态（如「部分继承」单独开关 / 「未配置」占位）—— 后端没有对应表示，
多出来的状态最终会静默折叠成 `null` 或对象，只是把歧义留给下一次保存。

## 决定 D-L2：写严读宽——输入护栏不是业务上限

**裁决**：写侧 `TRUST_LEVEL_LIMIT_MAX` 只挡手滑（冷却 30 天、每日上限 100000）；
读侧 `useTrustLevelsForm.ts` 的 `boundedLimit` **故意不设上限**，只把负数与非有限数收敛成 `null`。

**理由**：读侧一旦截断，服务端已经存着的更大值会在运营打开页面时被**静默改小**——
而运营根本没动过那个字段。两面不对称是刻意的：写侧要拦住明显错误，读侧要忠实呈现现状。
把两侧合成一个上限，等于让「读到什么」取决于前端版本。

**被否**：无被否记录。

## 决定 D-L3：受控输入必须显式回弹，fail-closed 不会自己重渲染

**裁决**：`change` / `blur` 时用同一套解析复核输入框内容；解析不出合法值就把输入框
**显式写回 prop 值**（`SFAdminTrustLevelLimitsTab.vue:74-92` 的 `onLimitCommit`）。

**理由**：`blockNonIntegerKey` 只拦 `keydown`；粘贴 `1.5` / `abc` 会绕过它走到 `setLimitValue`，
纯函数 fail-closed 返回**等值副本** → prop 没变 → Vue 不重渲染 → DOM 里留着那段脏文本。
运营会以为存进去了，保存后才发现没生效。受控组件里「拒绝修改」必须表现为「显式回滚 DOM」，
不能表现为「什么都不做」。

**被否**：只靠 `keydown` 拦截 —— 粘贴与输入法提交都能绕过，是最初实现被补掉的原因。

## 决定 D-L4：改限额不触发「档位结构变化」确认

**裁决**：限额编辑不参与 `tierStructureChanged`——该判据只比较 active 档位的 **id 序列**
（`useTrustLevelsForm.ts:722-724`）。所以改冷却 / 每日上限、切换继承与覆盖，保存时静默通过，
不弹「会重排所有人等级」的确认。

**理由**：结构确认回答的是「保存后谁落在哪一档会变吗」。限额改变的是「落进某档之后能做什么」，
不改变任何人的档位。把它算进结构变化，会让每次调冷却都弹一个陈述不实的大确认——
确认框一旦开始说谎，之后所有确认都会被当成噪声点掉。

**被否**：把限额纳入结构确认 —— 纯摩擦，且与「结构变化 = active id 序列变化」的既有定义冲突。
